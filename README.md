# FretFree

A complete static sheet-music library and private ABC notation workspace for GitHub Pages. No accounts, API keys, server, ads, remote soundfonts, or build step. All playable notation, original score assets, and the abcjs engine are bundled locally.

## Publish

Unzip this package into the root of a GitHub repository. Keep `.nojekyll`. In **Settings → Pages**, deploy from the branch and root folder containing `index.html`. Relative asset paths work at a project URL such as `https://username.github.io/fretfree/`. For local testing, run `python3 -m http.server 8000` in this folder and open `http://localhost:8000`. Offline use needs https (GitHub Pages) or localhost; the service worker covers the folder `index.html` is in.

## Library and permissions

See `scripts/library-stats.json` for exact counts and license versions. The original 841 score IDs and notation are retained. New editions use stable collection-specific IDs. Exact edition IDs/source URLs are deduplicated; different credited editions or settings of the same composition remain distinct.

- **O’Neill’s Music of Ireland (1903), 1,850 collection:** traditional historical tunes; modern ABC transcriptions are **GPL-2.0-or-later**, not public-domain notation. Original ABC bytes, source hashes, project contributor list, per-file transcriber credits where identified, copyright notice, and GPL v2 text are included. The separate 1,001 collection was not imported.
- **Open Hymnal:** only settings with an unqualified per-score public-domain declaration are admitted. The studio shows an **extracted upper voice**, with lyrics and lower voices omitted; some upper voices contain chords. Complete original ABC, including words, accompaniment, and declarations, remains available unchanged. Restricted settings are excluded. The endpoint named `OpenHymnal2014.06-abc.zip` currently contains later revisions as well; source revision text is retained rather than inferred from the archive filename.
- **Mutopia:** complete original PDFs and MIDI, editable LilyPond files or source ZIPs, contributors, edition provenance, hashes, and exact edition licenses. The editable studio part is an **upper-part practice reduction**, up to 32 bars, derived from MIDI and quantized to sixteenth notes. It omits accompaniment and performance markings. PDF/MIDI/source files are unchanged. Modern CC editions are labeled as licensed editions, separately from public-domain editions.
- **OpenScore Lieder Corpus:** 1,345 nineteenth-century songs (Schubert, Schumann, Brahms, Fanny Hensel, Clara Schumann, Josephine Lang, Louise Reichardt and 130 more composers), **CC0 1.0** MuseScore editions of public-domain compositions. The studio shows the **vocal line only**, converted from the pinned `.mscx` source by `scripts/import-openscore.py`; piano part and lyrics are omitted. See `RIGHTS.md` for the transformation and `scripts/lieder-exclusions.json` for the seven files left out.
- **OpenScore String Quartets:** 368 first-violin movements from 104 quartets (Haydn, Mozart, Beethoven, Emilie Mayer, Mendelssohn, Brahms, Saint-Georges, Borodin, Dvořák, Janáček and more), **CC0 1.0** MuseScore editions. Only composers who died before 1930 are included; see `RIGHTS.md`. Advanced level throughout.
- **Paul Hardy’s Tunebooks:** 554 traditional and pre-1930 session tunes from the Session Tunebook (2016 edition), Annex (2015) and Possible (2015) books (reels, jigs, hornpipes, polkas, waltzes, marches and airs from the British Isles and beyond) with guitar chords, **CC BY-NC-SA 3.0** transcriptions by Paul Hardy. The first **non-commercial** collection: free for lessons, practice and free events; not for sale, paid events or advertising-supported sites. Tunes by later named composers, known later compositions credited as traditional, and duplicates across the books are excluded; see `RIGHTS.md` and `scripts/pgh-exclusions.json`.
- **FretFree originals and teaching notation:** CC0-1.0 as in the baseline.

**Adding a tunebook you have downloaded.** Several non-commercial collections (Paul Hardy’s current editions and his Xmas Tunebook, Richard Robinson’s Tunebook, the Dottes books) cannot be fetched from the build environment. Download the ABC yourself and run `python3 scripts/import-pgh.py <session.abc> [<annex.abc> …]` for Paul Hardy’s books; the importer checks the licence declaration in the file header, keeps the original text and hashes, and refuses files without a cc by-nc-sa declaration. Other collections need a short importer of their own on the same pattern.

Filter by collection, exact notation/edition license, genre, difficulty, and score type. Search also includes collection and contributor credits. Accepted license families are PD, CC0, CC BY, CC BY-SA, CC BY-NC, CC BY-NC-SA, and GPL. Actual versions are preserved; no licenses are silently upgraded. Non-commercial editions are labelled on every card, in the rights box and in every export and share link. Difficulty labels are estimates.

**Skill filter.** Every score is tagged with what it practises, read from the music itself: Steps, Skips (thirds), Leaps, Repeated notes, Eighth notes, Sixteenth notes, Dotted rhythms, Triplets, Triple meter, Compound meter, Minor key, Accidentals, Chords, Rests, Wide range (an octave and a fourth or more) and Repeats. Filter by skill, click a tag on a card to filter by it (click again to clear), or type a skill in the search box. Tags live in `catalog-skills.js`, built by `node scripts/build-skills.cjs` from `skillTags()` in `score-tools.js`; `tests/check.cjs` fails when the file is stale. The original `skill` label on each card is kept.

**Try next.** Under a library score, the editor suggests three tunes that share its skill tags, at the same level or one level up, unfamiliar skills kept to a minimum. Scores you have opened are remembered in this browser (`fretfree-played`), marked **✓ Played** in the library, and moved down the suggestions so new tunes come first. There is no account; clearing site data clears the list.

**Blank sheets.** **Blank melody** (and *Write something new* on the library page) opens eight empty bars in one click: whole-bar rests in 4/4 and C major, with the first bar selected. Type A–G to write over the rests, or turn on Draw notes and click the staff: a click in a bar that holds a rest fills the rest from its start, so blank bars fill bar by bar. **＋ 4 bars** adds blank bars in the current meter, to every staff of a score with several (an `&` overlay gets them with its staff).

**New score templates.** **＋ New score** (in the studio and on My scores) opens a setup panel: Title, Template, Key, Time signature, Tempo, Pickup (none or 1–3 beats; a beat is a dotted quarter in 6/8, 9/8 and 12/8, and pickups that would fill a bar are greyed out) and Bars (1–64). The templates are **Melody**, **Lead sheet** (a melody with the key's tonic chord over the first full bar to start the chord line), **Piano** (right and left hand braced), **Duet** (two staves for the current instrument), **Melody and bass**, **SATB choir** (tenor in the octave treble clef) and **String quartet** (viola in alto clef, cello in bass clef). Each staff is one ABC voice block with `clef=`, `name=` and `snm=`, grouped by `%%score`, filled with whole-bar rests four bars to a line, so the bar check passes from the start. Piano, Melody and bass and SATB choir play on the piano sound and the string quartet on the violin, at concert pitch. Melody, Lead sheet and Duet keep the current instrument, and a duet's staves take its clef and transposition (two bass staves on cello, written pitch on clarinet). Click a rest on any staff and type to fill it; the octave follows that staff's clef. With nothing selected, letters go to the end of the top staff. A chord symbol on a rest stays on the beat when a note is written over it. Per-part instrument sounds come later.

**Backup and restore.** **My scores → ⬇ Back up** writes every saved score (with its earlier versions), favorite, played mark and practice setting on this device to one JSON file. In Chrome and Edge the browser's Save As dialog lets you put it in a synced folder (OneDrive, Google Drive, iCloud Drive) and FretFree remembers the file, so the next backup is one click; elsewhere it downloads. **⬆ Restore** merges a backup into the device: nothing is deleted, a score on both sides keeps whichever copy was saved more recently, favorites and played marks are combined, earlier versions are merged without duplicates, and settings are applied. The status line under the heading shows when the last backup was made and how many scores have changed since. Nothing leaves the device except the file you choose to save.

**Version history.** Saving a saved score again with changed music keeps the copy it replaces as an earlier version, so overwriting good work loses nothing. A card in My scores with earlier versions shows **History (n)**; it lists them newest first with the time each was saved and its instrument. **Preview** draws a version as the student read it (written pitch for the instrument, or concert pitch with Concert pitch on) with **▶ Play**, and **Restore** opens it in Compose as unsaved work on the same score. Restoring changes nothing stored; saving the restored version makes it the current copy and keeps the copy it replaced in the list, so a restore can be undone while that copy is in History. Versions are kept in this browser (`fretfree-versions`), up to 20 per score and about 1.5 MB in all, oldest dropped first; when storage is full they make room, so they never stop a save or a restore from backup. Deleting a score deletes its versions. Backups include them, and restoring merges them by save time; a score replaced by a newer copy from a backup keeps the old copy as a version.

**Share link.** The **Share link** button under a score builds a URL that carries the whole score: the ABC as it stands (edits included), the instrument, and the library edition it came from so its credits and licence notice travel with it. Nothing is uploaded; there is no server. The score is compressed (deflate) and base64url-encoded into the `#s=` hash, about 500 characters for a typical teaching tune; the panel warns above 8,000 characters, where some messaging apps truncate. Anyone who opens the link gets a copy marked "Shared score", which they can play, edit and save to My scores. Browsers without `CompressionStream` fall back to an uncompressed link that still opens everywhere.

**Embed code and QR code.** The share panel has three tabs. **Embed** gives code for a class website, Google Sites, Canvas or a blog: `<iframe src="…#e=…" width="100%" height="420" title="Score: …" loading="lazy"></iframe>`, with width (pixels or a percentage up to 100%) and height (200 to 2,000 pixels) fields. The `#e=` link carries the same payload as `#s=` and opens a read-only view: the score, Play, Stop, volume and speed, the credit line with any non-commercial label, and **Open in FretFree ↗**, which opens an editable copy in a new tab. A part for a transposing instrument (clarinet, trumpet, horn, saxes) is shown in written pitch and named under the title with how it sounds. Nothing on the embedded score can be selected or changed, an assignment's goals stay with the student's copy, and the view neither reads nor writes this browser's storage (no saved scores, played marks or drafts; the theme follows the device). **QR code** draws the share link as a QR code (SVG, error correction level M) for students to scan from a projector, with **Show full screen** where the browser supports it. It is drawn at 3 pixels per module, so longer links make larger codes; links over 997 characters also suggest full screen or the link. A QR code holds links up to 2,331 characters, comfortably a typical teaching tune; longer links get an explanation instead. The share panel closes when another score opens. The encoder is [qrcode-generator](https://github.com/kazuhikoarase/qrcode-generator) by Kazuhiko Arase (MIT), vendored unmodified as `vendor/qrcode.js` with its licence in `vendor/QRCODE-LICENSE.md`.

**▶ Listen** on a library card plays the line of music shown on the card (up to 20 seconds) and lights up its notes, so students can hear a tune before opening it. It uses the instrument filter's sound, or piano when no instrument is chosen. One preview plays at a time; click again, change a filter or favorite, open a score, or leave the library to stop it.

Public-domain declarations follow the source’s United States context. A public-domain composition does not make a modern transcription or arrangement public domain. Consult each edition’s rights notice and `catalog-rights.json` when sharing.

## Edit, play, and export

- Drag notes vertically to change pitch. Chords move together; rhythms and source positions are retained.
- Click a sheet-music note to select its **original concert-pitch ABC**, including transposing instruments. Selecting never moves the practice range.
- **Concert pitch** (a checkbox under Instrument, shown for the transposing instruments: Clarinet, Trumpet and Tenor sax in B♭, Alto and Baritone sax in E♭, and Horn in F) shows the score as it sounds: the key and pitches of the ABC source instead of the written part (Baritone sax plays the source an octave lower, and its caption says so), so a band teacher sees concert pitch and a student can check a part against the piano. Letters, drawn notes, accidentals, piano keys and MIDI keyboard notes enter the pitch shown, and note names, letters in noteheads, classroom colors and the Respell status line follow it. Playback and the ABC source do not change, and writing-prompt and assignment goals are still judged in written pitch (the checklist says so while Concert pitch is on). Prints and SVG exports show the score as it is on screen. Display only; remembered (`fretfree-concert-pitch`) and included in backups.
- **Play from a note**: double-click it, press <kbd>Space</kbd> with it selected (Space again stops), or choose **▶ Play from here** in its menu. Count-in applies; playback runs to the end of the practice range, or of the tune when the note is past it.
- **Note names** (Off / Letters / Do re mi) print under each note in the pitch shown: written pitch for transposing instruments, unless Concert pitch is on. Do re mi is movable do: do-based in major, la-based in minor, with sharp syllables for notes raised against the key signature and flat syllables for lowered ones. Display only; the ABC source never changes.
- **Letters in noteheads** (in the Note names list) writes each note's letter inside its notehead, and **Colors: Classroom** colors noteheads by letter in the Boomwhacker and handbell order: C red, D orange, E yellow (with a dark outline), F green, G light blue, A dark blue, B purple. Sharps and flats keep their letter's color; stems, rests and accidentals stay black. Both use the pitch shown (written pitch for transposing instruments, unless Concert pitch is on), appear in prints and SVG exports for worksheets, are remembered and included in backups, and never change the ABC source.
- **Zoom** (− / 100% / +, from 70% to 200%) and **Measures per line** (Auto, 2, 3, 4 or 6), just above the score, make the notation larger or easier to follow on projectors, small screens and phones. Zoom narrows the width the score is laid out in and the drawing is stretched back to the panel, so notes grow and lines hold fewer bars; above 100% on Auto the lines re-flow to fit. Titles, composer and other text around the music keep their 100% size, so long titles still fit. Each zoom step is announced in the status line. Clicking, dragging and drawing work the same at every size. Print / PDF and SVG use the same layout, so 200% gives a large-print copy; the SVG is as wide as the score. Re-flowing lays the score out twice, so very long scores redraw more slowly. Display only: the ABC source never changes. Both choices are remembered in the browser and included in backups.
- **Theme** (Auto / Light / Dark, in the header) sets the colors of the whole site. Auto follows the device's light or dark setting and changes with it. In the dark theme the score stays black on white, like a printed page, unless **Dark paper** (beside Zoom, shown only in the dark theme) is ticked; then the score, the library and History previews and the music-stand sheet use light ink on dark paper, with lighter selection and playback highlights. Body text keeps a contrast of at least 4.5:1. Prints and SVG exports are black on white in every theme. Both choices are remembered (`fretfree-theme`, `fretfree-dark-paper`) and included in backups; colors are tokens on `:root` in style.css.
- **Fingering**: Guitar shows tablature (standard tuning, via abcjs); Recorder shows baroque soprano recorder hole diagrams (thumb, then holes 1–7) for the beginner range C to D′ plus F♯ and B♭. Both can be switched off, appear in prints and SVG exports, and never change the source.
- **Writing prompts** (✎ Writing prompts in the studio): nine short assignments, beginner to intermediate, such as *"Write 4 bars in G major that move only by step. End on G."* Each opens a score with the right key, meter and tempo and one whole-bar rest per bar. Typing note letters on a rest writes over it (as in MuseScore), so bars stay full; the leftover rest stays selected. A checklist of goals (filled bars, allowed note lengths, start/end note, staying in key, steps, range, leaps, required notes or rests) ticks off live. Keys and goals are written pitch, so a B♭ clarinet asked for G major sees G major with Concert pitch off, and is judged in G major either way. The prompt stays attached when the score is saved. Each prompt has an example melody that `tests/check.cjs` verifies against its goals.
- **Assignments** (✎ Assignment in the studio): a teacher turns the open score into an assignment with a title, instructions (up to 2,000 characters) and goals picked from the same goal types as the writing prompts, such as filled bars, note lengths, the first or last note, the note that ends a given bar, steps, range, staying in key, or at least so many rests, eighth notes or leaps. Bar count, meter and written key (minor and modal keys too) come from the score, and goal labels are written for you (*"Bar 4 ends on D"*). The filled-bars goal needs every bar to be a full bar of the meter, so it is not offered on a score with a pickup, a short closing bar or a meter change. The builder keeps up with edits and instrument changes while it is open, and closes when another score opens. **Use and copy link** attaches it and copies a share link: the music on the page is the student's starting point, and each student who opens the link gets their own copy with the instructions above the score and a live checklist. The assignment is stored with the score, so it stays through Save, My scores (marked ASSIGNMENT) and backup/restore. In the link it rides as optional key `q`; payload `v` stays 1, built-in prompts still travel as `p`, and older versions of the app open the score without the checklist. Everything from a link or a backup goes through `validPrompt` (known fields and goal types only, finite whole numbers, text capped) and is shown escaped. Instructions print above the score; the checklist does not.
- **Turn in and Submissions**: on a score with an assignment or writing prompt, **Turn in** (next to Share link) asks for the student's name, remembered on the device as `fretfree-student-name`, and copies a link that adds the name (`n`), the time (`t`), the assignment's id (`x`) and each goal met or not (`g`) to the share payload (`v` stays 1). It also offers a `.json` file with the link, a readable summary and the credited ABC. A link made before the latest edit is taken away, so older work is not handed in by mistake. In **My scores → Submissions** a teacher pastes the links, one per line, or drops the files; each is decoded and checked (the name, the time and the assignment it carries, with goals and bar checks worked out again from the music), and lines that are not turn-in links are reported by number, as are files over 1 MB by name. Rows are grouped by assignment with the student, the time, goals met and bars to fix, sorted by name, goals met or time. **Open** shows the work in the studio under *"Turned in by …"* with **Previous** and **Next** through the class and a feedback box, whose text is kept per student as it is typed; **Copy return link** sends the music back with the feedback (`c`), which the student sees above the checklist, keeps when saving, and can answer by turning in again. Opening a turned-in link directly shows the same bar with **Add to submissions**, and unsaved-work recovery brings a submission back as one. **Save** on turned-in work makes a copy of your own, without the bar, that can be turned in. The inbox (`fretfree-inbox`) holds up to 200 submissions, with Delete and Clear all, and is included in backups; everything from a link, a file or a backup is checked field by field and shown escaped.
- **Keyboard note entry** (MuseScore-style): click a note, then <kbd>A</kbd>–<kbd>G</kbd> add notes after it in the nearest octave (letters are the written pitch for transposing instruments, or concert pitch with Concert pitch on), <kbd>R</kbd>/<kbd>0</kbd> a rest, <kbd>3</kbd>–<kbd>7</kbd> set the length from 16th to whole, <kbd>.</kbd> dots, <kbd>↑</kbd><kbd>↓</kbd> move by step (<kbd>Ctrl</kbd>: octave), <kbd>←</kbd><kbd>→</kbd> change the selection, <kbd>#</kbd> <kbd>-</kbd> <kbd>=</kbd> set sharp/flat/natural, <kbd>+</kbd> ties, <kbd>|</kbd> adds a bar line, <kbd>Delete</kbd> removes the note. The note menu also offers **Tie to next note** and **Insert after: Rest / Bar line**. Clicking a note keeps focus on the score so keys reach it; the ABC text is still selected. These edits also work on notes that open a slur `(C` or a tuplet `(3C`, and keep the `(` or `(3` in place.
- **Select, copy, paste and duplicate**: <kbd>Shift</kbd>+<kbd>←</kbd><kbd>→</kbd> or Shift+click selects a run of notes in one voice (Shift+click still sets the practice range too), and <kbd>Ctrl</kbd>/<kbd>Cmd</kbd>+<kbd>A</kbd> selects the whole voice. <kbd>Ctrl</kbd>+<kbd>C</kbd> copies, <kbd>Ctrl</kbd>+<kbd>X</kbd> copies and leaves rests of the same length, <kbd>Ctrl</kbd>+<kbd>V</kbd> pastes after the selection (or writes over a selected rest that is long enough, keeping what is left as a rest), and <kbd>Ctrl</kbd>+<kbd>D</kbd> repeats the selection right after itself and selects the copy. Whole measures copy with their bar line, so duplicating a bar gives a new bar. Pasted notes keep their length and pitch, in another score too: lengths are respelled for its unit length, and accidentals are added where the key or an earlier accidental in the measure needs them, so a note that was sharp only because of an earlier sharp in its measure is pasted sharp. Key, meter and unit-length changes inside a selection stay behind. Notes after a paste, cut, delete or accidental in the same measure keep their pitch too, with an accidental of their own where needed. Deleting whole measures takes a bar line with them, and a line left empty goes too (a blank line would end the tune). ↑↓, accidentals, <kbd>.</kbd>, <kbd>+</kbd>, <kbd>3</kbd>–<kbd>7</kbd>, <kbd>Delete</kbd> and <kbd>[</kbd> <kbd>]</kbd> (halve or double every length) act on every selected note, as do the notation toolbar's Length, Dot, Tie, ♯ ♭ ♮ and Delete buttons; letters and piano keys add notes after the last selected note. Pasting does not re-bar; the bar check reports any overflow. The **◂ Select / Select ▸ / Copy / Cut / Paste / Duplicate** buttons under the keyboard help do the same on touch screens. Each edit is one undo step. The clip stays in memory for this tab, and is also offered to the system clipboard as ABC where the browser allows.
- **Notation palette**: a toolbar above the score with **Length** (whole to 16th), **Dot**, **Tie**, **Rest** (turns the note into a rest of the same length and removes a tie into it), **Accidental** (♯ ♭ ♮ None, and **Respell**, as <kbd>Z</kbd>), **Beam** (**Join** removes the space before the next note so eighth notes and shorter share a beam; **Break** adds one) and **Delete**. The buttons light up to show the selected note's length, dot, tie, accidental and beam, so the state is visible at a glance. A button that does not apply to the selection is marked unavailable, and pressing it says why. Each press makes the same ABC edit as the matching key or note-menu item, as one undo step. With nothing selected, or with a rest selected, a length button sets the length of the next notes, like <kbd>3</kbd>–<kbd>7</kbd>. Buttons are at least 40 px for touch; the toolbar is one <kbd>Tab</kbd> stop, with <kbd>←</kbd><kbd>→</kbd>, <kbd>Home</kbd> and <kbd>End</kbd> to move inside it. It wraps on narrow screens and never prints. New notation tools add their groups here.
- **Measure tools** (**Measure ▾** in the notation toolbar) act on the selected note's measure, or on a selected bar line. **+ Bar before** and **+ Bar after** insert an empty bar (a whole-bar rest in the time signature in force, selected so typing writes over it) and **Delete bar** removes the measure, joining the bar lines on either side (a closing repeat, double or final bar line moves back); in a score with several staves every staff changes together, and an inserted bar goes inside the same repeat, ending or section. **Single**, **Double** and **Final** set the bar line after the measure, replacing the one there. **Start repeat**, **End repeat**, **1st ending** and **2nd ending** toggle on the bar line before or after the measure (`|:`, `:|`, `::`, `|1`, `:|2`; at the start of a line, `|:` or `[1`); an ending runs to the next repeat, double or final bar line. **Segno** and **Coda** go on the measure's first note and **Fine**, **D.C.**, **D.S.**, **D.C. al Fine** and **D.S. al Coda** on its last (one jump per note); playback follows them (see **Road-map playback**), and the status line says when a jump still needs a segno, a Fine or a coda sign. **Rehearsal mark** writes `[P:A]` and keeps marks lettered A, B, C in order (names of your own stay, and so do part letters when a header `P:` line orders the parts). **From here** menus change the **Time** signature (`[M:3/4]`, which the bar check then uses), the **Key** (`[K:G]`, asking Transpose notes or Keep notes, as the Key menu does; transposing moves the notes up to the next key change) and the **Clef** (treble, bass, alto, tenor, treble 8vb, in that staff only, compared with the clef shown, so Treble works on cello); from measure 1, time and key change the header. Where a line starts with an inline `[V:]` field, a change written there moves the voice field to a `V:` line of its own, since abcjs misreads key, time and clef fields right after an inline one. Buttons light up for what the measure has, and every change is one undo step. The dotted bar line is left out: abcjs 6.5.2 draws `.|` as a plain bar line with a dot over it. The pure helpers (`measureBounds`, `replaceBarLine`, `insertInlineField`, `insertMeasure`, `deleteMeasure`, `keyChange` and others) are in score-tools.js.
- **Articulations, dynamics and ornaments**: with a note selected, <kbd>;</kbd> <kbd>:</kbd> <kbd>&gt;</kbd> <kbd>"</kbd> <kbd>^</kbd> toggle staccato, tenuto, accent, marcato and fermata. The notation toolbar has the same five, the dynamics ppp, pp, p, mp, mf, f, ff, fff and sfz, and under **More** staccatissimo, up bow, down bow, breath mark, trill, mordent, turn and arpeggio; the note menu has the five articulations and the dynamics. Buttons light up for the marks the note has, and pressing a lit one takes it off. A new dynamic replaces the old one rather than stacking. Rests take a dynamic or a fermata, and invisible rests nothing. On a range selection the keys and buttons put a mark on every selected note that can take it, or take it off them all when they all have it; a dynamic goes on the first note. Marks are written into the ABC as decorations just before the pitch (after chord symbols, slur and tuplet openings and grace notes): staccato as `.`, the rest as `!accent!`, `!mf!` and so on; shorthands such as `L`, `H` and `T` are recognized and removed too. Each change is one undo step. Playback follows dynamics, accents and staccato, and plays sfz and marcato as accents; staccato notes sound for 60% of their length at any tempo. Ornaments play only roughly: abcjs trills and mordents a whole step from the note, and turns a whole step above and a half step below, whatever the key, so they can sound a half step off. Fermatas are held for twice their length. Every offered mark parses in abcjs without warnings (`fp` and `!staccatissimo!` do not, so they are left out).
- **Slurs, hairpins and trill lines**: select notes (Shift+click or <kbd>Shift</kbd>+<kbd>←</kbd><kbd>→</kbd>) and press <kbd>S</kbd> to slur them, or use the toolbar's **Slur**, **Cresc.**, **Dim.** and **Trill line** buttons. With one note selected the line goes to the next note in the same voice. The same press on the same notes takes the line off, and its button lights up while the selection has it. Slurs and trill lines run from the first to the last selected note, leaving out rests at either end; a hairpin may start or end on a rest. A new line replaces the lines of its kind that it covers or crosses (a crescendo also replaces a diminuendo), so slurring a longer run joins two short slurs into one. A slur around it stays, as a phrase mark, and so do lines that only meet it at its first or last note: one slur can start on the note where another ends, and <kbd>S</kbd> on either takes off just that one. Lines carry on into the voice's next block in scores that write their voices in turns (`V:1`, `V:2`, `V:1` …). Slurs are written as `(` … `)`, hairpins as `!<(!` … `!<)!` and `!>(!` … `!>)!`, and trill lines as `!trill(!` … `!trill)!`. Each change is one undo step and keeps the selection. abcjs draws only the tr of a trill line, so FretFree draws the wavy line after it. Hairpins change the playback volume note by note; trill lines print but the notes play as written.
- **Tuplets and grace notes**: with a note or rest selected, <kbd>T</kbd> or the toolbar's **Triplet** button splits it into a triplet, and the **Tuplet** menu into a duplet, quintuplet, sextuplet or septuplet. The note becomes the first member and rests fill the others, written as an explicit group such as `(3C/2 z/2 z/2` for a quarter in `L:1/4` or `(5:4:5C/2 z/2 z/2 z/2 z/2` for a half note; the first rest is selected, and each letter fills one rest at its own length, so the bar stays full, and notes shorter than a quarter are beamed together as they go in. Plain notes split into 3, 5, 6 or 7 in the time of 2 or 4; dotted notes into 2 in the time of 3, 5 in the time of 3 or 7 in the time of 6. The same count again takes the tuplet off while its other members are rests, and another count splits it again. **Delete** on a note in a tuplet turns it into a rest so the tuplet keeps its count, and on a rest takes off a tuplet of rests. **Grace** adds a grace note one step above the note (`{d}c`), **Slashed** makes it `{/d}`, **Grace ↑** and **Grace ↓** move only the grace note, and a lit Grace (or **Remove grace** in the note menu) takes it off. The note menu has the same tuplet counts and grace items. Each change is one undo step, and everything parses in abcjs without warnings and plays in time; grace notes take their time from the start of the note.
- **Chord symbols**: with a note or rest selected, <kbd>K</kbd>, the toolbar's **Chord** button or **Chord symbol…** in the note menu opens a box just above it. Type a symbol such as `G7`, `Bbmaj7`, `F#m7b5`, `C/E` or `N.C.` and press <kbd>Enter</kbd>; <kbd>Tab</kbd> saves and moves to the next note (<kbd>Shift</kbd>+<kbd>Tab</kbd> the one before, **Next ▸** on touch screens), <kbd>Esc</kbd> cancels, and an empty box removes the symbol. Clicking elsewhere saves it too. The symbol goes into the ABC as `"G7"` in front of the note; text annotations such as `"^Verse"` are left alone. A lower-case root is capitalized (`bb7` is `Bb7`), `nc` becomes `N.C.`, and `%` and backslashes are dropped (abcjs reads them as a comment and an escape). Text that is not a chord name, such as `Coda`, is still written, with a note that it prints but does not play. Each change is one undo step. On a transposing instrument (B♭, E♭ or F) the box shows and takes written pitch (concert pitch with Concert pitch on) and the source keeps concert pitch (written `C7` on clarinet is stored as `Bb7`). Chord symbols play as an accompaniment, and `N.C.` stops it until the next symbol; **Chords** next to Count-in turns it off for playback only (MIDI export keeps it), and is remembered and backed up. Transposing moves chord symbols by the interval's letters, so `Db` up a major 2nd is `Eb`, not `D#`, and leaves other text (`Coda`, `D.C.`) as written.
- **Lyrics**: with a note selected, <kbd>L</kbd>, the toolbar's **Lyrics** button or **Lyrics…** in the note menu opens a box under the note's staff, below any words already there. Type a syllable and press <kbd>Space</kbd> to go on to the next note, or <kbd>-</kbd> to end it with a hyphen (`Twin-kle twin-kle` fills four notes). <kbd>_</kbd> holds the syllable over the next note, <kbd>*</kbd> leaves a note without one, <kbd>Space</kbd> in an empty box passes a note as it is, and <kbd>-</kbd> or <kbd>_</kbd> in an empty box carries the word before on through the note. <kbd>Backspace</kbd> in an empty box goes back a note, <kbd>Tab</kbd> and <kbd>Shift</kbd>+<kbd>Tab</kbd> move on and back (**Next ▸** on touch screens), <kbd>Enter</kbd> starts the next verse at the note where typing started, and <kbd>Esc</kbd> or a click elsewhere saves and closes. Typing past the last note keeps the box open after it, so <kbd>Enter</kbd> still starts the next verse; words typed there are left out, and never reach the music. Rests are passed over, and on a rest the box opens on the next note. A syllable's own `-`, `_` or `*` (`mid\-day` in the ABC) shows in the box as a look-alike so it stays in the syllable, and <kbd>\</kbd> typed before one of these keys does the same. The words go into the ABC as `w:` lines under each line of music, one per verse, in the voice of the selected note; each saved syllable is one undo step, and changing one syllable leaves the others as they were. Earlier verses are padded with `*` so that each verse stays on its own row. A voice written after `&` shares the `w:` lines of its staff's first voice, so it takes no words of its own. Adding or deleting notes in a line with words under it shows a reminder to check that they still line up. Pasted words are spread over the notes the same way, and the keys work from phone keyboards too. Lyrics travel with saves, share links and the ABC, MusicXML, SVG and print exports (MIDI and WAV files carry no words), and survive transposing and instrument changes.
- **Hear notes** (on by default, next to Draw notes) plays a note once when you click it, type it or add it with the note buttons, draw it, move it with ↑↓ or a drag, change its accidental, or step to it with ←→; a chord plays all its pitches. It sounds the pitch playback gives the note, in the chosen instrument's sound: concert pitch with playback's octave (a cello sounds an octave below the source), octave clefs and `transpose=` included. It stays quiet during playback, and is remembered and included in backups.
- **Mixer** (in the transport, next to Chords) lists the score's voices, **Chords** (when chord symbols play) and the **Metronome**, each with **Mute**, **Solo**, **Volume** (0–150%) and **Pan** (left to right). Voices take their `V:` name (`name="Soprano"`), or Voice and their number; a one-voice score has Melody, and the voices of a `%%score` brace with one name take it with their ids (Piano (RH), Piano (LH)) or, for numbered voices such as an imported piano's, their places (Piano 1, Piano 2). Mute silences a track at once during playback, and muted tracks are not scheduled at all; Solo plays only the soloed tracks, and the metronome keeps time. Volume and Pan change as you move them, without restarting playback; a track that can be heard again picks up from where playback is. The count-in follows the metronome's level and pan even when it is muted. The mix is stored on the score by voice id: a saved score keeps it straight away (with a new saved time, so backups count the change, but without a new History version), others keep it when saved, and share links, embeds and drafts carry it (optional `m` key). A library score's mix goes on a copy of it, so opening the score from the library again starts without one. WAV export uses the mix and leaves out muted tracks. Reset clears it; ✕ or Esc closes the panel. Pan needs `StereoPannerNode`; browsers without it show no Pan sliders. `mixerTracks()` in score-tools.js lists the tracks, matched to the MIDI channels abcjs plays each voice on (an `&` overlay goes with its voice); `steadyLines()` keeps every staff in place on every line for playback and MIDI, so a voice keeps its channel when a voice above it runs out of lines before the others. Two voices written on one staff (`%%score (1 2)`) keep abcjs's own numbering when one ends before the other, so there Mute and Solo can reach the other voice's later notes.
- **Instruments**: flute, recorder, oboe, clarinet in B♭, bassoon, alto, tenor and baritone sax; trumpet in B♭, horn in F, trombone, euphonium and tuba; violin, viola (alto clef), cello and double bass; guitar, ukulele and bass guitar; piano, glockenspiel and voice. The Instrument menu and the library's Instrument filter are both built from `instruments` in `catalog.js`, grouped by family. Each instrument has its own sound, synthesized on the device: a waveform made from its harmonics (`partials`, through `createPeriodicWave`), an envelope (winds, brass, strings and voice swell in and hold; guitar, ukulele, bass guitar, piano and glockenspiel fade while the note is held) and, for flute, oboe, saxes, euphonium, strings and voice, a gentle vibrato that starts after the note begins. Each note is still one oscillator; a browser without periodic waves plays the instrument's basic wave. A part is written `shift` semitones above the concert ABC and plays `sound` semitones from it: Horn in F is written a perfect 5th above concert pitch, Tenor sax in B♭ a major 9th and Baritone sax in E♭ an octave and a major 6th (it plays the melody an octave lower, as cello and trombone do). Double bass and bass guitar sound an octave below their written part and glockenspiel two octaves above. Guitar plays as written, so playback, tablature and the piano strip agree; a real guitar sounds an octave lower. The caption under the title says how the instrument sounds against what is shown.
- **Piano keys** (under the note buttons) shows a five-octave piano strip under the score, kept at the bottom of the window and scrolled to the selected note or the instrument's range. Tap a key to write that note over the selected rest or after the selected note (or at the end); tapping keys in turn enters a melody at the current length, and each tap sounds with Hear notes. On a touch screen a key enters its note when the finger lifts, so swiping the strip or the page never enters one. Shift+tap, or holding one key while tapping others on a touch screen, adds the pitch to the selected note, or to the note just entered, as a chord (`C2` becomes `[CE]2`); <kbd>Shift</kbd>+<kbd>A</kbd>–<kbd>G</kbd> does the same from the keyboard, adding the letter just above the chord's top note. Keys are written pitch, so on Clarinet in B♭ the D key writes concert `C` (with Concert pitch on, keys are concert pitch). Notes are spelled for the key in force: in-key notes need no accidental, others take sharps in sharp keys and C, flats in flat keys, and a natural where an earlier accidental in the bar would change the note; a piano accidental never changes later notes in the bar (they get their own). The selected note's keys are lit and keys light as playback sounds them. From the keyboard, Tab to the strip, then ←→ move between keys, Enter adds the note and Shift+Enter adds it to the chord; other score shortcuts (3–7, Delete) still work there. The setting is remembered and backed up, and the strip is left out of print.
- **MIDI input** (next to Piano keys, shown only where the browser has Web MIDI, such as Chrome and Edge) enters notes from a USB MIDI keyboard. It asks the browser for MIDI access without SysEx and listens for note-on and note-off from every connected input; the status line names the connected keyboards and updates when one is plugged in or out, and says so plainly when access is blocked. Each note goes in like a piano-strip tap (written pitch, or concert pitch with Concert pitch on, over the selected rest or after the selected note, at the current length, spelled for the key), and notes played within 40 ms of each other go in as one chord. Held keys light the piano strip. Notes played while the score is playing, or away from Compose, are ignored, and so are drum pads (MIDI channel 10). Turning MIDI input off closes the keyboard's connection, so other apps can use it. Nothing is stored and no MIDI data leaves the page.
- **Respell** (<kbd>Z</kbd>, or **Respell** in the notation palette and the note menu for touch screens): turns the selected note or chord into its next spelling at the same pitch, such as `^C` into `_D` and back, or `E` into `_F`; D, G and A go through double flats and sharps. A chord moves as one and comes back in two presses: its other pitches swap (`[GCE]` becomes `[G^B,_F]`) while D, G and A stay plain, unless the chord has nothing else. The key signature and earlier accidentals in the bar are taken into account, and later notes in the bar keep their pitch: a natural is written where one is needed, and goes again when the old spelling comes back. Pressing again on the same note returns exactly the text it started from, and each press is one undo step. It works on one note or chord at a time, not on a range selection. `respell(text, key)` and `respellEdit()` in score-tools.js do the spelling.
- **Screen readers and the shortcut sheet**: the status line under the score (a polite live region) names the selected note, chord or rest as the staff shows it, with its length, written pitch, measure and beat ("Quarter note B♭4, measure 2, beat 1"; "Eighth note D5, measure 1, beat 2⅓" in 6/8, where a beat is a dotted quarter). It does so on every click and arrow key, and after every edit that has no message of its own, such as typing a note or moving one with <kbd>↑</kbd><kbd>↓</kbd>. <kbd>?</kbd> on the studio, or **All shortcuts** in the keyboard help line, opens a list of every editing command and its keys, grouped by task. Type in its search box to filter it ("tie" leaves Tie to the next note), choose with <kbd>↑</kbd><kbd>↓</kbd> or a tap, and <kbd>Enter</kbd> runs the command on the selected notes as one undo step. The list keeps the keyboard while it is open; <kbd>Esc</kbd> closes it and gives the keyboard back to the score. The palette's key hints come from the same table (`SHORTCUTS` in `shortcuts.js`); `describeNote` and `noteBeats` in score-tools.js do the wording.
- **Volume** changes loudness while the score plays. Every note and metronome click goes through one master volume control and, where the browser has one, a limiter, so chords and dense passages do not distort.
- **Undo / Redo** (buttons, Ctrl/Cmd+Z, Ctrl/Cmd+Shift+Z or Ctrl+Y; the shortcuts work on the score, in the ABC box and from menus, while the title and composer fields keep their own) covers every change to the score: dragging, drawing, the note menu, bar-check fixes, note buttons, header fields and typing. Each score edit is one step; a burst of typing in one place is one step. Undoing back to the opened text clears the unsaved-changes state; a new edit after undo clears redo. History resets when another score is opened.
- **Transpose…** (Score settings) moves the notes, key signatures and chord symbols by an interval (minor 2nd to octave, including augmented 4th and diminished 5th) up or down, or **to a key** the nearer way round. Spelling follows the interval: up an augmented 4th from C gives F♯ major, a diminished 5th G♭. **Selection only** transposes just the measures of the selected notes, or the shaded practice range, and keeps the key signature, adding accidentals where needed. Each transposition is one undo step; `clef=` and other key modifiers are kept. Keys are concert pitch, so on a transposing instrument (B♭, E♭ or F) the source moves in concert pitch and the written display follows.
- **Key** lists all 15 major and 15 minor keys plus Dorian, Phrygian, Lydian, Mixolydian and Locrian modes, with their sharps or flats. Choosing a key asks **Transpose notes** (move them to the new key) or **Keep notes** (change only the signature); a score with no notes yet changes at once. **Time signature** adds 2/2, 3/8, 5/4, 6/4, 7/8, 9/8, 12/8, C, C| and none (free time).
- **Unsaved-work recovery**: while a score has unsaved changes, a draft copy is kept in this browser (`fretfree-draft`, written two seconds after an edit and at once when the tab is hidden). If the tab is closed or discarded, the next visit shows *"Unsaved work from 3:42 PM: Title. Restore / Discard"*. Restore brings back the exact ABC, instrument, writing prompt and library credits, marked unsaved; it updates the same saved score when saved. Saving, Discard, replacing the score, or undoing back to the opened text clears the draft. A share link opened at start-up opens first and the offer follows. Each open tab keeps its own draft, so a second tab never replaces or clears the first tab's work; when more than one is waiting, they are offered newest first and Discard moves on to the next. Up to three drafts are kept, 500 KB in all, and drafts are not included in backups.
- **Offline and installing**: after one visit FretFree opens and works without internet: the library, saved scores, the editor and playback. A PDF or MIDI file from `scores/` works offline once it has been opened. A service worker (`sw.js`) keeps the copy: the page is fetched from the network first, so a new deploy shows on the next reload; `?v=`-stamped scripts and styles come from the cache (the stamp changes whenever a file does), the small ones kept at install and the large catalogs as they are fetched. An updated page becomes the offline copy only once all its files are kept, and only then are the old files dropped, so an update cut short leaves the previous copy working. Opened files under `scores/` are fetched again when online, so corrections reach students. It only ever fetches from this site. A notice in the header says when the device is offline. In Chrome and Edge, **Install app** in the header installs FretFree from `manifest.webmanifest` (icons in `icons/`, drawn from the SVGs by `node scripts/make-icons.cjs`); on an iPad or iPhone, use Share → Add to Home Screen. Browsers run service workers only on https and localhost; elsewhere the site works online as before. The About page says whether this browser has an offline copy, or whether part of it is missing.
- **Bar check** flags measures with too many or too few beats in plain words ("Measure 2 has 3 beats; 4/4 needs 4 beats. Add a quarter note or rest."), tints them on the score, and offers **Fill with a rest** for short bars or **Split the bar** when a long bar has a clean break. Pickups, section-closing bars that complete a pickup, `M:none`, multi-bar rests, tuplets and inline meter changes are understood. Library editions keep their historic irregular bars without warnings; only bars the student changes are checked. Overlays never appear in prints or SVG exports.
- Practice a range of measures: click a note, then Shift+click another to practice from the first to the second (Shift+click alone runs from that measure to the end); or choose **🔁 Practice from here** in a note's menu, or type the measures. The range is shaded on the score. **Loop** repeats it with no gap; **Metronome** clicks every beat, accented on beat one (compound meters count dotted beats); **Count-in** plays one bar first. **Speed trainer** raises the speed by 2, 5 or 10% after each pass until it reaches the goal. These toggles are remembered in the browser.
- **Feel** (Score settings): Straight, Light swing (60), Swing (66) or Hard swing (75). Swing plays pairs of eighth notes long-short: the off-beat eighth of each quarter beat starts late, at 60, 66 or 75% of the beat, and the note before it lasts longer. A beat with sixteenths, triplets or other off-beat notes plays as written, and so do meters that are not x/4 or x/2 (6/8 shows a note saying so). The setting is written into the ABC header as the printed tempo text and an abc2midi directive, `Q:"Swing" 1/4=120` and `%%MIDI swing 66`, so it prints, saves and shares with the score. Tempo text already there stays ("Allegro, swing"), and a score without a written beat gets the beat it already plays at, so the tempo does not change; the Tempo slider keeps the text. A tempo text with "swing" and no directive plays at 66, and an amount typed into the ABC shows as its own choice. Each change is one undo step. The note highlight, metronome and exported MIDI keep the straight beat. `swingNotes()` and `swingPlayback()` in score-tools.js do the timing.
- **Road-map playback**: playback follows D.C., D.S., D.C. al Fine, D.S. al Coda, To Coda and Fine, written as decorations (`!D.C.alfine!`, `!segno!`, `!coda!`, `!fine!`, `S`, `O`) or as text (`"D.C."`, `"^To Coda"`, `"Fine"`, `"^Coda"`), as Measure tools and many library tunes write them. A jump is taken on the last time through its measure. After it, repeats are not taken again (the last ending plays), and playback stops at Fine, or leaves at To Coda (or the first of two coda signs) for the coda. With no Fine or coda, a D.C. or D.S. stops at a fermata over a double, final or repeat bar line before it, as older scores mark the end (including O'Neill's `Hx||`), and otherwise plays to the end again. A multi-measure rest counts as all its bars. The note highlight, metronome, practice ranges, Play from here and the WAV file follow the jumps, and the status line names each jump as it is taken; a practice range stops where a jump leaves it. Fermatas are held for twice their length, and the notes after them start later. MIDI export stays in written order, and a score with no jumps and no fermatas plays exactly as before. `roadMarks`, `performanceOrder` and `performancePlan` are pure helpers in score-tools.js.
- **Record yourself** (● Record, next to Stop): **● Start recording** asks for the microphone (with echo cancellation, noise suppression and automatic gain off, so an instrument sounds as played), counts in 1 or 2 bars (`fretfree-record-count-in`, backed up), plays the practice range once at the playback speed, even with Loop or the speed trainer on, and records until the range ends or **■ Stop recording** (a stop in the count-in keeps no take). Each take is listed under the score with its length and time: **▶ Play** plays it alone, **▶ With score** plays it with the score from where the score started in the recording plus the device's latency, **Download** saves `<title> take 3.webm` (`.m4a` in Safari) and, for a library edition, a `credits.txt` with its notices, and **Delete** asks first. **Calibrate timing** plays 8 clicks, finds them in a recording and keeps the round-trip latency for this device (`fretfree-latency`, not backed up); until then the browser's own estimate is used, and older takes use a calibration made later. Takes are kept in IndexedDB (`fretfree-recordings`) per score (a saved score by its id, a library score by its id, others by an id they get when they open, which an unsaved-work draft keeps; the first save keeps them, even mid-take, though from a library edition it takes only the takes recorded since the edition was opened and leaves earlier ones with it; deleting a saved score deletes them; takes no score can reach are counted with **Delete them**, leaving out unsaved work open in another tab, which holds a Web Lock for its takes), never uploaded and not in backups, and the panel shows how much storage the site uses. A denied or missing microphone, or a browser without MediaRecorder, gets a plain message. `takeOffset()`, `audioOnsets()` and `estimateLatency()` in score-tools.js do the maths.
- Play from a chosen measure; speed is a percentage of the score’s original tempo. The speed slider preserves the ABC `Q:` tempo; the separate Tempo control edits it in the header's own note (with `Q:1/2=60` it reads 60 and moves to `Q:1/2=61`). A tempo plays in the note it names, in any meter: `Q:1/2=60` is 60 half notes a minute, also in 2/2 and C|. A score with no `Q:` plays at 180 quarter notes a minute (a half note at 90 in 2/2 and C|); in x/8 meters at 120 dotted quarters a minute in 6/8, 9/8 and 12/8, 180 dotted quarters in 3/8, and 180 eighth notes in 5/8, 7/8 and the rest. The Tempo control reads that tempo, and the note highlight, practice ranges, metronome and count-in follow the same tempo as the sound and the MIDI export.
- ABC exports preserve credits, exact licenses, source references, and change notices. FretFree ABC reimports restore this rights metadata. Exporting an imported credited ABC again replaces its notice block rather than multiplying notices.
- MIDI exports contain copyright/text events with credits and the corresponding editable ABC. Musical notes and timing are unchanged. Exported files use MIDI format 1 when a metadata track is added.
- SVG exports include every engraved SVG section, visible credits, and embedded editable ABC metadata.
- **WAV** (in the export bar) makes an audio file of the whole score as Play sounds it: the chosen instrument's sound, swing, the mixer's mutes, levels and pan, and the current playback speed, with **Include metronome** and **Include chords** (shown when the score has chord symbols) starting from the transport's switches. It is rendered on the device with `OfflineAudioContext` (16-bit stereo, 44.1 kHz, no count-in, scaled to 1 dB under full scale) and downloads as `<title>.wav`. A bar shows how far the file has got, in browsers that can report it, and closing the panel stops a file being made. A score that would play for more than 10 minutes at the chosen speed is refused with its length, since the recording is held in memory; about 50 of the longest library pieces, mostly string quartet movements, are that long at 100%, and their MIDI export has no limit. The file's INFO chunk carries the title and composer, and for library editions the license (ICOP) and the full credit with the editable ABC (ICMT); a score of your own carries only its title and composer, or a copyright line kept from an imported file. Browsers without `OfflineAudioContext` say so and suggest MIDI. `wavBytes()` in score-tools.js writes the file and `creditedWavInfo()` in rights-tools.js its text.
- **MusicXML** exports (`.musicxml`) are for moving a score into MuseScore, Noteflight, Finale, Sibelius or Dorico. They are written at concert pitch from the ABC: parts from voices (staves braced in `%%score {…}` become one part with several staves), key, meter and clef changes, notes, rests, chords, ties, tuplets, grace notes, chord symbols, lyrics, dynamics, hairpins, articulations, ornaments, slurs, repeats with 1st/2nd endings, and tempo. A length no single note has, like the `z5` left in a 6/8 bar, becomes tied notes or several rests. A part the ABC transposes only for playback (`transpose=`, `%%MIDI transpose`) keeps its written notes and gets a MusicXML transposition, so it sounds as it does in FretFree. Credits and the exact license go in the file's rights field, on page 1, and in a `fretfree-rights` field for re-import; GPL editions also carry the GPL text and the editable ABC.
- **Open ABC or MusicXML** also opens MusicXML (`.musicxml`, `.xml`, or compressed `.mxl`, up to 5 MB) from MuseScore, Noteflight, Finale, Sibelius or Dorico, converted to ABC at concert pitch on the device. Staves become voices with their part names and clefs (a piano's staves are braced), with notes, rests, chords, ties, tuplets, grace notes, key, meter and clef changes, transposing parts, chord symbols, lyrics, dynamics, hairpins, articulations, slurs, repeats and endings, and tempo. The status line lists anything left out in plain words, such as pedal marks or tremolos. A FretFree MusicXML export comes back with its rights metadata (the credit and source fields, with links only to web pages); another program's copyright line is kept as `%%abc-copyright`, shown under the score and carried by later exports.
- Print/PDF exports retain the rights notice and links. GPL scores additionally print the editable ABC and complete GPL v2 text as an appendix. Keep these pages with redistributed copies.
- When distributing CC BY adaptations, preserve attribution, license, source, and change notices. CC BY-SA adaptations also retain the same edition license. GPL derivatives retain credits, license, change notices, and corresponding editable source. The app’s MIT code license does not replace music licenses.

Piano selections do not generate accompaniment; Guitar shows tablature and Recorder shows fingering diagrams (see Fingering above). Sound is synthesized locally, with no samples or soundfonts (see Instruments above). Instrument selection changes written pitch/clef while MIDI stays in concert pitch (bass-range instruments and baritone sax sound an octave lower in playback, double bass and bass guitar two octaves lower, glockenspiel two octaves higher).

## Saved-score compatibility

The keys remain exactly:

```
commonnote-scores-v1
commonnote-favorites-v1
```

The update performs no migration, clearing, or ID replacement. Earlier versions of saved scores live under their own key (`fretfree-versions`), so the saved-score list keeps its format. Existing saved ABC and favorites remain intact. Added metadata also survives saving new scores. Storage belongs to the browser and origin: use the same hosting origin to retain it, and export ABC backups before clearing browser data or moving to another host.

## Source audit and validation

`catalog-rights.json` records per-edition rights; `provenance/` preserves listing evidence; `scores/<id>/` preserves original assets and `RIGHTS.txt`; `licenses/` retains collection notices and license texts. `scripts/` includes import inputs, exclusions, duplicate reports, and library statistics. `VALIDATION.md` records the completed checks.

Code layout: `theme.js` (sets the stored theme on the page before it first paints; the only script not deferred), `shared.js` (DOM and storage helpers, `KEYS`, `currentInstrument()`, the theme controls), `library.js` (cards, filters, previews, suggestions), `editor.js` (the open score, rendering, undo, bar check, draw mode, note menu, keyboard entry, fingering, prompts), `playback.js` (audio scheduling, metronome, trainer, note highlight), `keyboard.js` (the on-screen piano and MIDI input), `assignments.js` (the assignment builder), `turn-in.js` (Turn in, the Submissions inbox and feedback), `record.js` (recording takes, the takes list and calibration) and `app.js` (wiring and start-up, loaded last). `score-tools.js` holds pure functions over parsed ABC; `rights-tools.js` the credits and licence text; `musicxml.js` the MusicXML export and import. Run `npm run format` before committing; CI checks it.

Tests (development dependencies are not required to host; `package.json` exists only for them):

```
npx playwright install chromium

```

`npm run test:all` runs everything. The same steps run in GitHub Actions (`.github/workflows/test.yml`) on every pull request and push to `main`.

It stamps every local script and stylesheet in `index.html` with `?v=` set to a hash of their contents, so visitors get fresh code exactly when it changes, without a hard refresh. `tests/check.cjs` fails if any stamp is missing or no longer matches the files.

Set `CHROMIUM_PATH` to an existing Chromium executable if needed. ## Anthology investigation

The Public Domain Song Anthology’s official publication confirms unrestricted reuse, and the UVA dataset identifies CC0-1.0.
